## 一、总体评价

系统架构清晰，与开发宪章 5 条准则高度一致（万物皆 fd、对象状态机、O(1) 调度、caps 令牌、用户态 FS 驱动）。代码量控制得当，模块边界合理。但存在 **3 个会导致运行时崩溃/数据损坏的确定性缺陷**（RUN 死锁、FAT 簇重复分配、TSS ESP0 未随任务切换），以及若干边界校验缺失。

## 二、已修复 BUG（13 处）

### S1 严重（崩溃 / 数据损坏）

| # | 位置 | 问题 | 修复 |
|---|------|------|------|
| 1 | `src/user/ufs.cpp` `alloc_cluster()` | `read_fat()` 把 EOC（≥0xFF8）归一化为 0，与"空闲簇(0x000)"无法区分 → 扫描时把已有文件链尾的 EOC 条目误判为空闲**重复分配** → 新旧文件共享同一簇，数据互相覆盖损坏 | 新增 `fat_entry_raw()` 读取原始 FAT 值（不归一化），`alloc_cluster` 用它判断 `== 0` 才是真空闲 |
| 2 | `src/kernel/syscall.cpp` SYS_EXIT 分支 | 子进程退出只把阻塞父进程 `state=READY` **不重新入队**（父进程 waitpid 阻塞时已被移出就绪队列）→ 父 Shell 永远得不到调度 → **RUN 后死锁/僵尸** | 唤醒父进程时 `list_add_tail(&parent->list, &ready_queue)` |
| 3 | `src/kernel/syscall.cpp` `sys_waitpid()` | 子进程被调度器选中时 `list` 节点已出队（next/prev 置 0），waitpid 回收时无条件 `list_del(&dead_child->list)` → **解引用空指针崩溃** | `if (dead_child->list.next) list_del(...)`，sibling 节点始终摘除 |
| 4 | `src/kernel/syscall.cpp` IOCTL_GFX_TEXT | 原实现对用户结构写 `p->t[63] = 0`，用户只传 5 字节头时**越界写用户内存** | 改为只读拷贝到内核缓冲（`p[5..67]` 复制进 `char tb[64]`），不再写回 |
| 5 | `src/drivers/gfx.cpp` `fill_rect()` | 无边界裁剪，用户 ioctl 传任意坐标/尺寸 → **越界写显存/内核内存** | 增加屏幕范围裁剪（`set_pixel` 已有裁剪，`fill_rect` 补齐） |
| 6 | `src/kernel/task.cpp` `schedule()` | 切换任务后**不更新 TSS ESP0** → 子进程在用户态触发 syscall/中断时，CPU 用父进程的内核栈顶 → **父子共用内核栈，栈互相覆盖崩溃** | 恢复上下文前 `user_tss_set_esp0(nt->kernel_stack + 4096)`（含 `#include "kernel/user.h"`） |

### S2 中等（功能缺陷 / 潜在崩溃）

| # | 位置 | 问题 | 修复 |
|---|------|------|------|
| 7 | `syscall.cpp` `sys_sbrk()` | 使用全局 `g_user_pd` + 全局 `user_break` → fork 后子进程 sbrk 映射进**父进程页表**，子进程堆缺页 | 映射改用 `current_task->paging`（break 仍全局，标记为已知限制） |
| 8 | `syscall.cpp` `sys_fork()` | 复制 fd 表时管道引用计数未 +1 → 父子任一关闭管道即提前 `kfree` → **use-after-free** | 复制 fd 时对 type 2/3 执行 `pipe->refs++` |
| 9 | `task.cpp` `schedule()` + `task.h` | 原代码 `r->eax = nt->pid == current->pid ? pid : 0` 把**所有跨任务切换**的 eax 清零（正常抢占也会清）→ 用户程序寄存器被破坏 | `task_struct` 增加 `eax` 字段，调度保存/恢复各自 eax；fork 子进程初始 eax=0（`task_init/task_create/task_create_user` 同步初始化） |
| 10 | `task.cpp` `task_exit()` | 对不在就绪队列的任务无条件 `list_del` → 链表破坏 | `if (current_task->list.next) list_del(...)` |
| 11 | `syscall.cpp` `sys_fwrite()` | 缺 `str==null` 检查 → typ=4 时 `gfx.puts_utf8(nullptr)` 崩溃 | 入口加 `if (!str) return -1` |

### S3 轻微（边界防御）

| # | 位置 | 问题 | 修复 |
|---|------|------|------|
| 12 | `src/fs/ext2.cpp` | 块缓冲固定 1024B，`s_log_block_size>0`（4KB 块）时 `read_block` 写 4096 字节 → **栈溢出** | 所有块缓冲统一 4096B，`init()` 限制 `block_size_ <= 4096` |
| 13 | `src/drivers/gfx.cpp` `utf8_decode()` | 字符串末尾截断的多字节 UTF-8 序列越界读 `s[1]/s[2]` | 增加续字节存在性检查 `s[1] && s[2]` |

## 三、审查确认的遗留问题（未修复，纳入规划）

| 级别 | 问题 | 说明 |
|------|------|------|
| 架构 | **用户页从不回收** | `PagingManager::~` 只释放页表页，被映射的数据页（代码/栈/sbrk 页）泄漏。每次 Shell 重启约泄漏 21 页（~86KB），32MB 内存可支撑 ~300 次重启，属"慢泄漏" |
| 架构 | **用户态协作式调度** | isr.cpp PIT 只在 ring0 调度；用户态任务仅在 syscall 点让出（waitpid/sleep/yield）。无限循环程序无法被抢占（Ctrl+C 走信号路径可中断） |
| 架构 | **bcache 与用户态写不一致** | 用户态 ufs 通过 SYS_DISK_READ/WRITE 直读磁盘绕过 bcache；内核 fat12 走 bcache → 用户态写后内核侧读到旧数据。需 bc_invalidate 接口 |
| 功能 | 鼠标坐标硬编码 clamp 1023×767 | 与 VBE 实际分辨率无关，大分辨率屏幕鼠标到不了右下角 |
| 性能 | `sys_open` 每次 kmalloc 64KB | 小文件也占满 64KB，fd 表 16 项 = 最多 1MB |
| 安全 | 用户态 argv 指向内核 `g_user_args`（无 USER 位）| 带参启动的程序访问 argv 会 #PF（当前所有用户程序不用参数） |
| 安全 | `task_send_signal` 搜不到 BLOCKED 任务 | waitpid 阻塞的进程收不到信号 |
| 安全 | 信号 handler 地址检查区间过宽（0x20000~0x410000）| 0x20000-0x400000 未映射，误跳进未映射区仍会 #PF |
| 内核 | `sys_exec`/`sys_exec_fd` 失败路径泄漏 | `mm_alloc_page` 中途失败时 new_pd 未 delete、已拷贝页未回收 |
| 内核 | 内核态 PIT 调度 + syscall 期间 IF 关闭 | 设计自洽（int 0x80 门清 IF），但 sys_sleep 的 sti/hlt 与调度器交互需留意 |

## 四、后续开发规划

### Phase 3 收尾（内存与进程正确性）— 建议下一迭代
1. **用户页回收机制**（最高优先）：`PagingManager` 记录每个映射页的物理地址并统一释放；或引入"用户页表引用计数"。修复 exec/fork 失败路径泄漏。
2. **调度器抢占完善**：用户态任务周期计时（每 tick 累计运行时长，超时进 syscall 强制让出），或用户态 PIT 调度 + 独立内核栈校验（TSS ESP0 已就位，风险降低）。
3. **bcache 一致性**：新增 `bc_invalidate(lba)`；SYS_DISK_WRITE 后失效对应缓存条目；用户态 FS 写流程接入。
4. **fd 内存优化**：`sys_open` 按 `vfs_stat` 大小分配（≤64KB），或改为固定 8KB + 按需增长。
5. **信号补全**：搜索含 BLOCKED 任务的全局任务表；handler 地址区间按实际映射页校验。

### Phase 4a：网络栈
1. 网卡驱动：RTL8139（PCI 简、QEMU 默认支持）→ 环形 DMA 收发
2. 链路层 ARP → 网络层 IPv4（ICMP ping 可测）
3. 传输层 UDP → TCP（三次握手、seq/ack、窗口最小实现）
4. **准则一落地**：socket 抽象为 fd type 7，`SYS_IOCTL` 扩展 bind/connect/send/recv 语义；内核仅做协议栈，应用层 DNS/HTTP 放用户态
5. 测试：与宿主 QEMU 用户网络（-netdev user）互通 HTTP

### Phase 4b：图形增强
1. 现有 IOCTL（fill/line/rect/pixel/text）之上补：`bitblt`、`带调色板的 8bpp 屏幕`、硬件光标
2. 输入事件队列：鼠标/键盘 → 内核事件 ring → fd 读取（准则一：input 也是 fd）
3. 窗口管理：用户态 WM（每个窗口一个 fd 后台缓冲 + 合成器）
4. 中文字体已就绪（GNU Unifont 27826 字），可做文本 UI 库

### 生态（Phase 2/3 延伸）
- 用户态 C 库完善：`printf` 系列、动态内存、文件 API（已有 libc.h 雏形）
- 可执行格式：ELF 加载完善（多段映射、bss 清零已验证）+ 动态库（作难）
- 批处理解释器（demo.bat 曾搁置，根因：fat.dir() 偶发 #UD + 执行流切换）— 归入用户态库修复
- 工具链固化：提交构建脚本 + 文档化 LLVM/NAMM/QEMU 环境（本机缺失）

### 质量基线
- 每次 Phase 验收：QEMU 冒烟（启动 → LS/CAT → CREATE/RM → RUN → fork/exec → 连续 Shell 重启 20 次检查内存不下降）
- 建立 `tools/qemu_auto.py` 自动化冒烟脚本（串口断言）
