## Phase 3 收尾（建议下一迭代，按优先级）

### P0：用户页回收
- `PagingManager::~` 区分内核克隆页（PSE，无 USER）与用户映射页（4KB PTE，may have USER）
- 用伴生 bitmap 记录每页是否由本 PD 分配，析构时统一 `mm_free_page`
- 顺手修复 `sys_exec`/`sys_exec_fd` 失败路径的 new_pd 泄漏
- 量化收益：每次 Shell 重启不再泄漏 ~86KB，32MB 内存可支持数千次重启

### P0：bcache 一致性
- 新增 `bc_invalidate(u32 lba)`，SYS_DISK_WRITE 后调用（内核或用户态驱动）
- 用户态 ufs 的 `disk_write` 改成：先 SYS_DISK_WRITE、再通知 bc_invalidate → 需要跨地址空间
- 方案 A：内核 SYS_DISK_WRITE 自动 invalidate 自身缓存（无需用户配）
- 方案 B：引入 SYS_CACHE_INVAL lba=count 给用户调用

### P1：自动冒烟扩充
- `tools/qemu_auto.py` 验证 CREATE（短文件名 + 短内容，例如 "CREATE A 1" 11 字符）
- 验证两次 CREATE 不互相覆盖（修复 BUG#1 端到端）
- 验证连续 20 次 Shell 重启后内存不低于阈值（修复 P0 后）
- 验证 fork+exec 链 100 次循环无泄漏

### P1：UI 调试输出重构
- `ushell` 改为从 `printer` 接口输出，允许运行时切换"framebuffer / 串口 / 双输出"
- 自动化测试运行时让屏幕输出同步镜像到串口 → 用文本对比代替像素分析
- 受益：测试可读、调试用户态不再盲

### P2：run.bat/run.py 升级
- `make` 命令缺 `clang64` PATH → 写一个 `tools/env.sh` 一键设置（source 即可）
- run.bat 加 `format=raw` 显式 → 解决普通用户的 raw 写限制警告

## Phase 4a：网络（约 4–6 周）

### M1 网卡驱动
- RTL8139（QEMU `-device rtl8139` 默认支持，PCI 简单）
- 收发环形 DMA + 缓冲管理
- 准则一：网卡 = fd type 8（`SYS_OPEN("/dev/rtl8139")`）

### M2 协议栈
- ARP → IPv4（含 ICMP，ping 可达）
- UDP
- TCP（最小：三次握手 + 状态机 + 简单窗口）
- 全在内核侧作为协议分发，**应用层放用户态**（准则五）

### M3 socket fd 接口
- `SYS_IOCTL` 扩展：`BIND` / `CONNECT` / `LISTEN` / `ACCEPT` / `SEND` / `RECV`
- 阻塞语义：套接字 fd 状态机带超时（准则二）
- 用户态示例：`http_get` / `dns_resolve`

### M4 工具
- Wireshark 抓包验证
- 自动化测试：guest ↔ host 互 ping & HTTP

## Phase 4b：图形（约 3–4 周）

### M1 图形原语扩展
- bitblt（位图传输）
- 8bpp 调色板模式
- 硬件光标（`mcursor_update` 提速）
- 现有 IOCTL 7 命令已够用，扩参更丰富

### M2 事件队列
- 输入 = fd type 9（`SYS_OPEN("/dev/input")` + `read` 拿到事件）
- mouse / keyboard 统一抽象为 `event_t { type, x, y, key, btn }`
- 准则一：图形 = fd，事件 = fd

### M3 用户态窗口管理器
- 每个窗口 = 用户态 task，拥有自己的 fb 缓冲
- 合成器定期把所有窗口通过 bitblt IOCTL 合成到主屏幕
- 示例：ushell 跑在内层，WM 嵌套管理

### M4 字体增强
- 已有 16×16 点阵字库（27826 字）
- 补充 8×16 矢量变体（`font8x16` 已有）
- Win-1252 / GB18030 编码适配
